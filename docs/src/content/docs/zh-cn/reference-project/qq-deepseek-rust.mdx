### QQ Memory 指令

```text
/memory
/remember 我偏好简短回答
/forget 1
/forget all
/memory compact
/reset
```

/memory 查看当前会话的有界摘要、事实和保存状态；/remember 显式加入事实；/forget INDEX 删除指定事实，/forget all 清除全部记忆。/reset 清摘要和最近问答，保留明确事实；/stop 只取消待发送结果。清除成功须以持久化结果为准，无卡不能冒充已清空 SD。

网页 Memory 预览最多 8 KiB，不包含会话键或最近聊天原文；需要管理码。网页编辑须先停止机器人并等后台操作完成，避免与模型写回并发覆盖；这不是完整记忆导出功能。

### QQ 图片输入

DeepSeek 官方 [Vision 指南](https://api-docs.deepseek.com/guides/vision/) 支持 Flash 图片输入，支持能力必须按当前模型目录检查，不能假设所有 DeepSeek 模型都支持。v0.5.0 每条最多接 2 张 JPEG、PNG、GIF 或 WebP，图片 URL 必须为 HTTPS 且不超过 4096 字节；附件声明大小最多 8 MiB、单边最多 8192 像素。ESP 不下载或独立测量图像，这些声明不等于实际内容校验。

图片由 DeepSeek 获取，ESP 只提交有界图片内容块；带签名的附件 URL 不进入长期记忆或一般日志。QQ 图链可能过期或无法被 DeepSeek 访问，模型不支持或输入被拒绝时应明确报告，不能把文字回复冒充识图。

### QQ 远程入口与功能边界

QQ 官方按钮可以跳转网址、回调或发送指令，但不提供本项目所需的通用 HTTP 内网隧道；发出 192.168.x.x 链接不会让外网访问到该网页。[官方按钮说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/msg-btn.html) 当前使用允许名单内的 QQ 文字指令进行远程状态、灯控和记忆操作，网页仍在局域网，尚未部署公网入口。

OTA 更新、完整 Memory 导出及账户额度管理尚未实现；不将这些功能算入本次验收。

## v0.4.0：自然语言工具与 SD 历史检索

可以直接说“帮我查一下 ESP32-S3 官方资料”“读一下 https://example.com/ 并总结”，或“之前聊过的彗星方案是什么”。模型自行选择 Search、Fetch 或当前会话的 SD 历史检索；问候和普通改写通常直接回答，不额外增加一次规划请求。工具选择由模型决定，并非每次措辞都保证相同选择。

每次请求最多执行 2 次工具调用，顺序执行；达到上限后禁用工具并生成最终回答。自然语言网页结果每次最多带入 4 KiB 正文，编码后的工具结果最多 8 KiB，模型请求序列化最多 48 KiB；原来的总时限、取消和 QQ 回复期限继续生效。联网调用使用 DeepSeek 账户额度，网页及历史资料始终是不可信参考资料。

历史档案按私聊用户或群＋发言人隔离，每个会话循环保存最近 32 轮已成功写入工作记忆的问答；每轮用户文字最多 1024 字节、助手文字最多 2048 字节，按 UTF-8 边界截断并标记。SD owner 逐条读取并校验 CRC，只返回最多 3 个各 768 字节的命中片段，没有常驻向量数据库或完整历史 RAM 索引。档案不会扩大原有 48 KiB 工作缓存预算。

`/memory search 关键词` 可直接查看命中片段。`/reset` 和 `/forget all` 同时清理该会话历史档案；成功清除前须同步双槽删除水位。SD 不可用时不会假装检索成功，档案写入失败可通过 history_failed 等状态检查。升级前已经被摘要替换的旧原文无法恢复，新档案从升级后的完成问答开始累积。

## 私密配置导入

在 .private/provision.json 中填写自己的配置，并将文件权限设为 0600。此目录已被 Git 忽略；不要把密钥放进源码、公开日志或命令行参数。所有字段都必须存在，generation 由设备在导入时重新分配。

```json
{
  "version": 1,
  "generation": 0,
  "wifi_ssid": "YOUR_WIFI_SSID",
  "wifi_password": "YOUR_WIFI_PASSWORD",
  "deepseek_key": "YOUR_DEEPSEEK_API_KEY",
  "deepseek_model": "MODEL_FROM_CATALOG",
  "qq_app_id": "YOUR_QQ_APP_ID",
  "qq_app_secret": "YOUR_QQ_APP_SECRET",
  "allow_users": ["YOUR_USER_OPENID"],
  "allow_groups": []
}
```

将示例占位值替换为真实配置。QQ 使用官方 Bot 凭据和用户 openid；群消息还要求群 openid 在 allow_groups 中，允许的群不会自动授权未列出的发送者。DeepSeek 模型填写账户实际可用的模型 ID。

```sh
chmod 700 .private

```

导入前工具先检查固件身份，导入后只返回脱敏状态。若 bot 正在运行，先执行 bot stop 并等待停止，再替换配置。Wi-Fi 在开机或配置导入后自动连接；网络失败采用退避重试，wifi status 可查看连接、IP 和校时结果。

## 灯控与基础诊断

板载灯是 GPIO48 上的一颗 WS2812，使用 GRB 顺序和 RMT 数据，不能按普通 GPIO 灯控制。通道值限制为 0 到 32；先用低亮度验证红、绿、蓝及熄灭。

```sh
python tools/boardctl.py --led-test
python tools/boardctl.py "led rgb 16 0 0" "led status"
python tools/boardctl.py "led off"
```

driver_applied 表示驱动最后成功发送的值，不能代替实物观察。status 还报告 Flash、PSRAM、内部堆、栈水位、看门狗及串口队列溢出计数；selftest 执行硬件自检，reboot 请求重启。

## NVS 与存储行为

配置使用 qqds_v1 命名空间的 cfg0 和 cfg1 双槽。新配置只写非活动槽，校验、提交并回读成功后才切换；一个槽损坏时仍检查另一个槽。初始化出错不会自动擦除 NVS。

nvs test 写入新的测试序号和随机值；在重启前后分别执行 status，比较 nvs.probe，可核验持久化。配置和灯控不依赖 SD；v0.2.0 的短会话仅在 RAM，v0.3.0 新增下文所述 SD Memory 和会话按需恢复。新格式不扫描或自动迁入旧工程会话。

## QQ 回环与 DeepSeek

以下命令只存在于带 bot 功能的固件。启动服务要求 Wi-Fi 已连接、时间已同步，且已填写 QQ 凭据和允许名单。先执行回环模式验收 QQ 与灯控，再切换模型模式。

```sh
python tools/boardctl.py "bot start echo" "bot status"
python tools/boardctl.py "bot stop"
python tools/boardctl.py "deepseek probe"
python tools/boardctl.py "deepseek status"
python tools/boardctl.py "bot start deepseek"
```

bot stop 是协作停止；切换前等待 bot status 中的 active_workers 降为 0，保留的 bot 状态对象不表示线程仍在运行。即使关闭意图写入 NVS 失败，本地停止仍会执行；错误回复会说明重启后自动启动可能尚未禁用。

deepseek probe 检查鉴权和模型目录；deepseek test 发起一次短推理，会使用 API 额度。诊断在后台执行，使用 deepseek status 查看完成结果。EchoOnly 模式可以同时运行这些诊断；DeepSeek 模式需要先停止，并等待现有诊断或通知结束。

在允许的 QQ 会话中，可测试 /ping、/echo 文字、/status、/led on、/led off、/led rgb R G B、/led status、/reset 和 /stop。只有模型模式将普通文字交给 DeepSeek；远程配置、任意 GPIO 和脚本执行没有开放。

显式启动成功后，模式意图保存到独立的 bot_mode 键。重启时等待硬件检查、Wi-Fi 和校时就绪后恢复相同模式；bot stop 保存关闭意图，缺少记录时默认关闭。v0.3.0 的会话在再次访问时从可用 SD 读取；内存恢复与服务自动启动分开验收。

本地 bot notify-owner 文字 命令只向配置中的唯一 owner 发起一次明确的主动通知；结果在 bot status 或 deepseek status 中查看。它不会自动重试，重启或自动恢复服务也不会重复发送。只有确实要发送通知时才执行此命令。

## 局域网网页管理

v0.2.0 在 Wi-Fi 联网后启动管理页。从同一局域网浏览器打开 status 中 wifi.ip 对应的 HTTP 地址；页面本身可打开，所有 /api/ 状态、配置和操作请求都必须使用管理码。

```sh
python tools/boardctl.py "web pairing"
```

web pairing 只通过本机串口显式返回管理码，不通过 QQ 或网页公开。管理码拥有配置权限，请私密保存；页面仅在当前浏览器会话保存它，点击“锁定”会清除。当前管理页使用 HTTP，应在可信局域网中访问。

网页提供概览、连接配置和检查工具。r1 已实测登录、鉴权、来源、大小限制和 AI 诊断；r3 已在真板 Search 期间切换概览、开灯、停止机器人、关灯及刷新，返回工具页后 3 个来源的结果仍保留。空错误记录正确显示“当前没有错误信息”，三份静态资源经板端 HTTP 取回的哈希与源码一致。

保存配置前先停止机器人并等待工作线程退出。网页读取配置不会返回原密码或密钥；秘密字段留空表示保留原值。保存带当前 generation，版本已变化时拒绝覆盖，重新读取再编辑；修改 Wi-Fi 后可能需要在新网络重新查找设备地址，保存本身不会自动重新启用机器人。

## SD 卡适配

v0.2.0 启动时只在独立 worker 中尝试挂载一次。总线使用板载 SDMMC slot1、1-bit、20 MHz；挂载失败不阻塞联网和聊天，不自动格式化、修复或无限重试。没有卡检测引脚，错误不能被直接解释为“没插卡”。

新固件只在 /sdcard/qq-deepseek/ 下执行读写检查、列表和诊断日志，不扫描、迁移或删除旧系统目录。32 GB 实卡报告容量 30,985,420,800 字节，64 字节排他写、同步、读比删通过；r1 网页卸载后 QQ、Web、Wi-Fi 仍正常，自检报告 sd_required=false，重挂、自检和列表再次通过。这不等于已验证物理拔卡开机或所有旧文件完整性。

```sh
python tools/boardctl.py "sd status"
python tools/boardctl.py "sd test"
python tools/boardctl.py "sd list"
```

sd mount、sd unmount、sd test 和 sd list 都在后台执行。每次操作后用 sd status 等待 busy=false，再查看 last_result 和 fault，然后发下一条操作。取卡前执行 sd unmount；I/O 失败或超过操作期限后会禁用进一步读写，清理失败需要重启，状态仍可通过串口和网页查看。

Boot 诊断日志仍只含固定事件和数字时间，达到 64 KiB 后停止增长；v0.3.0 经用户授权另在 /sdcard/qq-deepseek/memory/ 保存会话、事实和摘要。两种文件用途分开，记忆不写入 NVS，也不混入一般诊断或公开日志。

## DeepSeek Search 与 Fetch

联网工具直接调用 DeepSeek 官方 [Search / Fetch API](https://api-docs.deepseek.com/guides/search/)，使用同一 DeepSeek 密钥。v0.4.0 普通文字对话可由模型按需调用搜索、网页读取和当前会话历史检索；以下显式命令仍可使用。

```text
/search ESP32-S3 官方文档
/fetch https://api-docs.deepseek.com/guides/search/
搜索：ESP32-S3 官方文档
抓取：https://api-docs.deepseek.com/guides/search/
```

也支持“联网搜索”前缀。QQ 路径先取得搜索摘要或网页 Markdown，再让模型总结并附上本次返回的真实来源链接；网页工具栏和串口诊断返回来源及有界预览。它们不代表已独立核实网页说法，也不会把网页中的指令当作设备命令。

搜索词最多 128 个 Unicode 字符；Fetch 要求 HTTP/HTTPS 主机地址，拒绝明确的本地地址和带账号密码的 URL，并有正文、上下文和总时限限制。过长资料会明确截断或报超限，空结果、API 拒绝和超时会明确报告；调用会使用 DeepSeek 账户额度。

```sh
python tools/boardctl.py "deepseek search ESP32-S3 官方文档"
python tools/boardctl.py "deepseek fetch https://api-docs.deepseek.com/guides/search/"
python tools/boardctl.py "deepseek status"
```

直接诊断可在 EchoOnly 模式运行，DeepSeek 模式需先停止；同一时间只运行一项诊断。QQ 普通会话仍受原来的允许名单、取消、消息期限和短会话上限约束。

## 错误与重连记录

v0.1.0 已复现 op7 正常重连被误记为 Transport 错误；原 6／7 次累计错误无法逐条归因。v0.2.0 独立统计重连、AI 计数和最近 16 条 recent_errors，它们随运行时重建而重置。r3 已完成停止路径的关键真板回归，但 SDK 异常挂起的超时保护、完整 QQ 检索问答及长期运行仍待验，不能用计数清零或短测试替代。

r3 的清理线程独占 SDK 资源并按 stop→destroy 退场；网关最多等待 12 秒，超时锁存清理错误和“需重启”，同次启动不再创建新连接。断网 4 秒恢复后的真板停止用时 1.6901 秒，workers=0、cleanup_failed=false、cleanup_active=false，随后 Echo 恢复 QQ READY；SDK 底层仍可能挂起，异常清理超时分支尚未人工注入。
