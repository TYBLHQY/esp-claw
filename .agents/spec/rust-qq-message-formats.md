## 2026-10-21 QQ material-management update (research baseline)

User supplied the official 20261021 changelog; the live official material-management page was read on 2026-10-22. At that research point, v0.6.1 used /files -> file_info -> msg_type7 for /image and /file; v0.7.0 now adds the independent SD material path described below.

- Official docs: https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/material-management.html ; changelog: https://bot.q.qq.com/wiki/develop/api-v2/changelog.html#_20261021 .
- Upload flow: POST /v2/media-images/prepare with file_name/file_size/content_type/md5/sha1, PUT raw image bytes to presigned_url with the exact declared Content-Type, then POST /v2/media-images/complete with upload_id and ETag MD5. Complete returns image_id/url/ttl/temporary preview_url.
- Markdown syntax: ![caption #800px #400px](qqbot-media://image/v1/<token>), optional dimensions; use only actual returned references, never let a model invent tokens.
- Platform bounds: png/jpeg/gif/webp, <=10MB per image, <=100 active images per robot, upload tasks expire after4h, presigned URL lifetime is expires_in. References are robot-bound and expire after90 days without a successful message reference; each successful use extends expiry. Do not persist preview_url.
- Future bounded ESP approach: the sole SD owner streams chunks to hash and upload; never load a whole image or require an external image host. Cache only bounded image_id/reference/expiry metadata on SD; do not put platform reference tokens in general conversation memory. Reuse existing workers and keep final message attempts inside the shared reply budget/no unknown replay rules. Existing arbitrary output-URL submission must remain separate because this API requires actual bytes and hashes.
- Research-stage pending items were Rust implementation, account permission, private/group display and C2C stream compatibility; all were subsequently exercised for the v0.7.0 fixtures below. The material documentation demonstrates ordinary Markdown msg_type2; do not infer streamed-image compatibility or group streaming. This feature does not add AI image generation.
